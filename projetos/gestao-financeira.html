Gestão Financeira

App de finanças pessoais feito de ponta a ponta: front em Angular 22 e API própria em Node, com Fastify e PostgreSQL. Contas, transações, cartões com fatura, orçamentos, metas e dashboard. O que me interessava eram as regras difíceis e o que costuma ficar de fora de projeto de portfólio.

Front-end
Angular 22, Signals, Signal Forms, Angular Material, Vitest, Playwright
API
Node 26, Fastify 5, Zod 4, Drizzle, PostgreSQL, Testcontainers
Links
Demo · Front · API

✱Destaques do front

  • Faturas calculadas

    O saldo de uma fatura passa para a seguinte, com pagamento parcial e travas em cadeia: uma compra antiga não muda fatura já paga. Compras parceladas, com antecipação e cancelamento, e estornos.

  • Código do erro na tela

    Cada requisição leva um X-Request-Id. Uma falha inesperada mostra o começo dele, que leva à linha do log na API; erros do navegador também são relatados à API.

  • CSP aplicada

    Content-Security-Policy em produção, com o hash do único script inline. Os E2E falham se aparecer qualquer violação.

  • Acessibilidade testada

    Verificação com axe-core nos testes E2E, nos temas claro e escuro, e layout responsivo até o celular.

✱A API

  • Concorrência

    ETag e If-Match recusam edições sobre dados desatualizados com 412, em vez de sobrescrever a alteração de outra aba.

  • Pagamento sem duplicar

    Idempotency-Key guardada com o hash da rota e do corpo, e trava da linha do cartão contra dois pagamentos simultâneos.

  • Sessão segura

    Cookie __Host- com Argon2id, revogação imediata, verificação de origem e rate limit no login.

  • Isolamento provado

    Um teste chama toda rota com o id de outro usuário e falha se surgir rota nova fora dele. Chaves estrangeiras compostas com o dono.
